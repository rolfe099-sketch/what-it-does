n = 27 sessions per condition, one model family (Claude), nine task scenarios. Figures are counts of sessions, not of tool calls. Full method, raw transcripts and limitations →

Agents did not fail to use the tool because the description was unclear. They read a one-line summary, decided it was not worth opening, and moved on. Moving the identical text into the file the agent always reads took adoption to every session, with nothing else changed.

If that result holds beyond this sample, a large amount of agent tooling currently shipping is never being called at all — and the authors have no way to find out.

What this does not show One model family. Nine scenarios. No other MCP servers tested. We do not yet know whether this generalises to other agents, other tools, or longer sessions.
Reproduce it The harness is MIT licensed and needs no changes to the server under test. It reads session transcripts only.

    Where you put the instructions decides whether the agent uses the tool

    Identical instructions, two locations. Adoption moved from 22% to 100% of sessions. Placement, not prose, was the deciding variable.

  • 002MeasuringIn progress

    How much of an agent's token spend never reaches a decision

    Wide, parallel work run through a batch engine instead of the agent's own context. First pass across nine jobs put aggregate output-token savings at 64.7%. Being re-run with per-scenario figures published.

Cadence Studies are re-run when a major model ships, and at minimum every quarter. Superseded figures stay published with a dated revision note. Nothing is silently edited.

How this is paid for

The studies, the findings and the harness are free and always will be. The archive — every historical run, the raw transcripts, and the machine-readable series — is a paid subscription, and that is what funds the measurement.

No vendor pays for placement here, and no result is shown to a vendor before publication. If that ever changes it will be disclosed on this page before it is true, not after.
