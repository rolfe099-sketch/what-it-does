The harness · MIT licensed

Find out whether agents are calling your tools at all

Every study on this site is produced with this harness. It reads session transcripts and reports whether the agent invoked your tool, when it should have, and when it shouldn't have.

Why it's free A measurement you cannot reproduce is an advertisement. The harness is free so the findings can be checked.

Install

Requirements Python 3.11+. Core has no dependencies; provider SDKs are optional extras.

Terminal

pip install -e ".[all]"

Write a specification

A specification lists the jobs to run and, for each, whether your tool should fire. That second field is what makes false positives measurable — a tool that fires on everything is not adopted, it is noisy.

myspec.json

{
  "tool": "aion_map",
  "jobs": [
    {
      "id": "review-wide",
      "prompt": "Review every file in src/ for error handling.",
      "should_fire": true
    },
    {
      "id": "single-edit",
      "prompt": "Rename the variable `tmp` in utils.py.",
      "should_fire": false
    }
  ]
}

Run it

Start with --dry-run. It prints the plan and the estimated cost as a range, and spends nothing.

Terminal

$ aion bench myspec.json --dry-run
2 jobs · 1 tool · 0 API calls
estimated cost: 6 model calls, roughly $0.11-$0.48

$ aion bench myspec.json --repeat 3
  triggered    5/6    83%
  false pos    0/3     0%
  1st call ok  5/5   100%
  all calls ok 5/5   100%
  excluded     0      (incomplete or unauthenticated sessions)

Reading the output

What each metric means, and what it does not
MetricMeansDoes not mean
triggered The tool fired on jobs where it should have. That it did the job well.
false pos The tool fired where it should not have. That the result was wrong — just unwanted.
1st call ok The first invocation returned a valid result. That the agent understood the result.
excluded Sessions dropped before scoring. Failures — these never reached a model.

That last row matters more than it looks. A session that died on authentication produces zero tool calls, and if you count it as a data point you will report a low adoption rate that is really an infrastructure problem. The harness excludes those before scoring and tells you how many it dropped.

Spend ceiling Set --max-spend on every run. Ceilings stop new dispatch; calls already in flight will finish, so the true stop is slightly above the number you set.
Caching Cache keys hash the model, settings and fully-resolved prompt. Re-running an unchanged job costs nothing.
Small samples lie Three repeats is enough to spot a broken setup, not enough to publish. Our own studies use 27 sessions per condition and we still call that provisional.

What it will not do

It does not execute shell commands. That is deliberate and permanent — a measurement tool that can run arbitrary commands on your machine is a liability, not a feature.

It does not judge output quality. It measures whether a tool was reached for and whether the call succeeded. Whether the answer was any good is a different study.

It does not phone home. No telemetry, no usage reporting, nothing leaves your machine except the model calls you asked for.
