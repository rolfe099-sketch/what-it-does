Where you put the instructions decides whether the agent uses the tool

Identical instructions, two locations, twenty-seven sessions each. Adoption moved from 22% to 100%. The wording never changed.

Confidence Low-to-moderate. The effect is large and the direction is unambiguous, but the sample is one model family on nine scenarios. Do not cite this as a general law of agent behaviour.

The question

Agent platforms offer more than one place to describe a tool. Some files are read at the start of every session. Others are optional: the agent sees a one-line summary and decides for itself whether to open the full description.

Tool authors generally assume that a good description is what drives adoption. This study tests a different variable: whether the file the description sits in matters more than the description itself.

Method

Two conditions were prepared with byte-identical instruction text. In the first, the text lived in an optional skill file. In the second, the same text was placed in the always-read context file. Nothing else differed — same tool, same server, same nine task scenarios, same model.

Each condition was run across 27 sessions. A session counts as adopted if the agent invoked the tool at least once. Adoption is derived from the session transcript alone, by pairing tool_use blocks with their matching tool_result blocks. The server under test was not modified and did not report on itself.

Sessions that never reached the model, failed authentication, or terminated incomplete were excluded before scoring, so that infrastructure failures could not masquerade as a decision not to call the tool.

Why transcripts Measuring from transcripts rather than server logs means the method works on any server, including ones we did not write and cannot instrument.
Known weakness "Invoked at least once" is a blunt measure. It does not capture whether the agent used the tool well, or whether it should have called it more than once.

In the optional-file condition the agents were not confused by the instructions — in the majority of sessions they never read them. The transcripts show the agent encountering the one-line summary and electing not to investigate further. The decision was made before the description was ever seen.

Moving the identical text into the always-read file produced adoption in every session, with no cases of the tool being invoked when it should not have been.

Limitations

Stated plainly, because they are the part most likely to be dropped when this gets quoted:

  • One model family. Every session ran against Claude. Nothing here establishes how other agents behave.
  • Nine scenarios. They were chosen as representative of wide, parallel work. A different task mix could produce a different rate.
  • One server. No other tool servers were tested. A tool with a more obviously urgent purpose might be sought out from an optional file.
  • Binary measure. Adoption is "invoked at least once". Quality of use is not measured.
  • Point in time. Agent platforms change how they load context. This result has a shelf life, which is why it will be re-run.

If you find this result does not reproduce in your setup, that is a useful outcome and we would like the transcripts. Corrections are published in the corrections log with the original figures left visible.
